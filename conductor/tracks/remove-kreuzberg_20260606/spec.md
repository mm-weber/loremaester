# Specification: Remove kreuzberg — permissive, per-page OCR pipeline

**Track ID:** remove-kreuzberg_20260606
**Type:** Refactor
**Priority:** High
**Created:** 2026-06-06
**Status:** Draft

## Summary
Remove the `kreuzberg` dependency from the OCR path and replace it with a direct, per-page,
permissively-licensed pipeline: `pypdfium2` render → per-page `pytesseract` (default) / `easyocr`
(GPU opt-in) → concatenate.

## Context
v0.1 release-prep debugging proved kreuzberg is both a functional and a license liability:
- EasyOCR-on-PDF was broken in kreuzberg 4.5–4.8.x (undeclared `pdf2image`/`pymupdf` dependency).
- EasyOCR still returns empty for **multi-page** PDFs in 4.9.9 (single page works: p0 = 236, p3 =
  1302 chars; 8 pp & 16 pp = 0), with no error raised. tesseract and *standalone* EasyOCR read the
  same rendered pages fine → the fault is kreuzberg's multi-page wrapper.
- kreuzberg (≥ 4.6) is Elastic License 2.0 (source-available, non-OSI) — even the tesseract path pulls it.

Full evidence: `requirements/v0.2/requirements_v0.2.md` R-1 / R-1E. EasyOCR itself is Apache-2.0 —
calling it directly per page is permissive **and** fixes the bug.

## Acceptance Criteria (EARS notation)

### Dependencies & licensing
- [ ] THE OCR module SHALL NOT import or depend on `kreuzberg`.
- [ ] THE OCR module SHALL depend only on MIT-, Apache-2.0-, or BSD-licensed Python packages.
- [ ] THE OCR module SHALL render PDF pages using `pypdfium2`.
- [ ] THE shipped OCR path SHALL NOT declare `surya`, `pymupdf`, or `paddleocr` as dependencies.

### Rendering & OCR
- [ ] WHEN an image-only PDF is submitted THE OCR module SHALL render each page to a raster image with `pypdfium2`.
- [ ] THE OCR module SHALL OCR each page independently and concatenate the per-page text in page order.
- [ ] THE OCR module SHALL NOT pass an entire multi-page document to a single OCR/extraction call.
- [ ] THE OCR module SHALL default to the `tesseract` backend.
- [ ] WHERE the `easyocr` backend is selected AND a CUDA device is available THE OCR module SHALL run EasyOCR on the GPU.
- [ ] WHERE the `easyocr` backend is selected AND no CUDA device is available THE OCR module SHALL run EasyOCR on the CPU.
- [ ] WHEN a page is OCR'd THE OCR module SHALL record that page's text and a per-page confidence or detection count.

### Errors & edge cases
- [ ] IF the selected OCR backend package is not installed THEN THE OCR module SHALL exit with an error naming the missing package and its install command.
- [ ] IF `pypdfium2` is not installed THEN THE OCR module SHALL exit with an actionable error.
- [ ] IF a page yields no text THEN THE OCR module SHALL record a low/zero-confidence warning for that page and continue with the remaining pages.
- [ ] IF every page of a document yields empty text THEN THE OCR module SHALL report a clear, document-identifying failure and SHALL NOT ingest empty content.
- [ ] WHILE `INGEST_DEBUG` is set WHEN a page fails THE OCR module SHALL print the full traceback.

### Integration & consolidation
- [ ] THE `ingest_books.py` and `extract_text.py` scripts SHALL obtain OCR text only from the shared OCR module.
- [ ] WHEN `ingest_books.py` classifies a PDF as image-only THE script SHALL OCR it via the shared module and ingest the result into R2R.
- [ ] THE ingest path SHALL preserve the current R2R document title and default-collection behavior.
- [ ] WHEN a PDF is text-native THE `ingest_books.py` script SHALL use R2R native ingestion without OCR.

### Tests & docs
- [ ] THE OCR test suite SHALL pass without `kreuzberg`, `tesseract`, `easyocr`, or `poppler` installed (backends + renderer mocked).
- [ ] THE repository documentation SHALL NOT instruct users to install `kreuzberg`.
- [ ] WHEN OCR is documented THE documentation SHALL describe only the `pypdfium2` + `tesseract`/`easyocr` pipeline.
- [ ] THE `THIRD_PARTY_LICENSES.md` file SHALL NOT list `kreuzberg`.

## Dependencies
- **Add:** `pypdfium2` (Apache/BSD). **Reuse (already in repo):** `pytesseract`, `Pillow`, `pdfplumber`.
  **Opt-in:** `easyocr`, `torch` (Apache/BSD).
- **Reference pattern already in-repo:** `scripts/ocr_preprocess.py` (render → per-page OCR → ingest).

## Out of Scope
- Full consolidation of `ocr_preprocess.py` onto the shared module (R-2) — optional follow-up.
- `paddleocr` backend — dropped.
- v0.1-vs-v0.2 release timing of the rollout — decided separately.

## Technical Notes
Per-page is the core design: the single-page mode is proven to work; the bug appears only when a
multi-page document is processed as one unit. Rename env `KREUZBERG_OCR_ENGINE` / `KREUZBERG_OCR_LANGUAGE`
→ `OCR_ENGINE` / `OCR_LANGUAGE` (read the old names as a fallback). Keep the existing `is_image_pdf`
routing, SHA1 dedup, and the temp-`.txt` `file_path` ingest (preserves R2R title + default collection).
